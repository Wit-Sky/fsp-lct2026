# 0. Краткое описание подхода

**Задача.** Платформа подбора ИТ-специалистов, где работодатель сам выходит на кандидата в категоризированной базе
и приглашает его с указанием зарплаты.

**Механика подбора — «заявка на команду».** Работодатель описывает потребность: специализацию, грейд, навыки с весами,
зарплату от–до с пометкой «гросс» или «нетто», формат работы. Система показывает подходящие категории
(«специализация + грейд») с числом подтверждённых кандидатов и ранжированную подборку. У каждого места в подборке есть
объяснение «почему он здесь»: какие навыки совпали, какой грейд подтверждён тестом и на каком процентиле категории,
какие результаты ФСП учтены. Работодатель отправляет адресное приглашение с зарплатой; контакты кандидата открываются
только после того, как кандидат принял приглашение или сам откликнулся на вакансию.

**Механика тестирования.** Грейд кандидата подтверждается только экспресс-тестом по категории (10 заданий, 5 минут).
Задания — параметрические шаблоны: каждый шаблон по сиду кандидата генерирует свои числа, имена, фрагменты кода
и порядок вариантов, правильный ответ вычисляет код. Сложность задаёт шаблон, а не случайность, поэтому разные
варианты сопоставимы. Уровень кандидата оценивается по модели Раша, задания подбираются адаптивно.
Слитые ответы бесполезны: у другого кандидата другие варианты. Это проверено симуляцией (раздел 4).

**Почему так.** Резюме можно приукрасить, а одинаковый для всех тест быстро утекает в сеть. Персональные варианты
с калиброванной сложностью дают сопоставимую оценку и устойчивы к утечке. Результаты ФСП учитываются как
дополнительный сигнал только внутри категории, поэтому кандидат без истории ФСП проходит весь путь наравне с другими.
