## 11.10, 17:20 МСК — серверные пункты взяты по поручению Евгения
- Счётчик подбора: `total` считается после фильтров и до `limit`; UI показывает «Найдено» и отдельно «Показано»,
  если карточки ограничены. Соседние грейды и «Только с ФСП» меняют реальный счётчик. Веса и порядок подбора не менялись.
- Каждый `POST /api/auth/demo/candidate` сбрасывает только демо-кандидата: тесты, категорию, внешние связи,
  импортированные результаты, приглашения, отклики, ответы на задания и сессии связывания ФСП.
  Профиль восстанавливается с ФИО «Демо Кандидат»; ФСП ID снова свободен. При DEMO_MODE=0 демовход отключён.
- ФСП ID: авторизованный `POST /api/auth/fsp/start` → код на 60 секунд → браузерный GET authorize.
  JWT сессии больше не попадает в URL. Код и callback используются по одному разу, привязаны к кандидату и
  HttpOnly cookie браузера; OIDC state живёт 10 минут. На HTTPS cookie Secure; ответы no-store/no-referrer.
  Хэши и сроки хранятся в PostgreSQL, поэтому одноразовость действует между процессами API и после перезапуска.
- Выбор «без истории ФСП» сохраняется через `PUT /api/me/profile {fsp_skipped:true}` и сразу обновляет экран.
  Чистый браузер видит тот же выбор до первого теста. Старые отметки localStorage больше не влияют на путь,
  в том числе после нового демовхода. Ошибки сохранения и старта связывания показываются пользователю.
- Миграция `0004_fsp_authorization_and_skip` следует за существующей `0003_regular_tasks`.
  Обновление существующего профиля на PostgreSQL 16 проверено: данные сохранены, fsp_skipped=false.
